## EXECUTIVE SUMMARY

The OMV Agent project adds a Flask AI backend and a JavaScript widget injected into the OMV admin UI. The live OMV nginx config uses strong transport security (TLS 1.2/1.3, HSTS, X-Frame-Options, nosniff) but the CSP contains unsafe-eval and unsafe-inline for script-src, providing ZERO XSS protection -- all XSS defence must be code-side. Three architectural decisions create unavoidable high-risk surface areas: (1) the Flask backend may be reachable without OMV session auth; (2) the widget injects DOM content into a privileged admin interface where XSS equals root compromise; (3) the AI processes user-supplied natural language that may be reflected back into the UI. All four CRITICAL issues below block shipment.

## CRITICAL ISSUES - Block Ship

---

### CRIT-1: Unauthenticated LAN Access to Backend

**Severity:** CRITICAL
**Category:** Broken Access Control (OWASP A01:2021)
**Location (planned):** nginx conf for /omv-agent/, app.py

**Risk:** Any LAN device can query the AI agent and access OMV system information without authenticating to OMV.

**Description:** OMV uses auth_request in nginx location blocks to enforce session auth. A new /omv-agent/ block added without auth_request bypasses this entirely. Flask binding to 0.0.0.0 makes it LAN-reachable on :5000 without nginx.

**Required nginx location block:**
```nginx
location /omv-agent/ {
    auth_request /rpc.php;
    auth_request_set $auth_status $upstream_status;
    proxy_pass http://127.0.0.1:5000/;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Real-IP $remote_addr;
    client_max_body_size 8k;
}
```

**Required Flask binding:**
```python
if __name__ == "__main__":
    app.run(host="127.0.0.1", port=5000, debug=False)
```

**Required defence-in-depth in Flask:**
```python
@app.before_request
def require_local_proxy():
    if request.remote_addr != "127.0.0.1":
        abort(403)
```

### CRIT-2: XSS via innerHTML in widget.js

**Severity:** CRITICAL
**Category:** XSS (OWASP A03:2021)
**Location (planned):** widget.js

**Risk:** AI response rendered via innerHTML allows injected JavaScript to execute in the OMV admin context. OMV admins have root-equivalent OS privileges. XSS = full system compromise. The live CSP contains unsafe-inline in script-src so injected inline scripts WILL execute. The CSP provides zero XSS mitigation.

**Prohibited patterns - none of these may appear in widget.js for AI response data:**
```javascript
element.innerHTML = response.answer;          // FORBIDDEN
element.outerHTML = response.answer;          // FORBIDDEN
document.write(response.answer);              // FORBIDDEN
element.insertAdjacentHTML("beforeend", x);   // FORBIDDEN
eval(anything);                               // FORBIDDEN unconditionally
new Function(userInput)();                    // FORBIDDEN unconditionally
setTimeout(userString, 0);                    // FORBIDDEN
setInterval(userString, 0);                   // FORBIDDEN
```

**Required pattern - only permitted methods for AI response text:**
```javascript
element.textContent = response.answer;        // SAFE
// OR:
element.appendChild(document.createTextNode(response.answer)); // SAFE
```

If markdown rendering is required: use DOMPurify.sanitize(marked.parse(response.answer)) and assign sanitized result to innerHTML. Both libraries must be loaded from self only and pinned to specific versions.

### CRIT-3: Command Injection via Subprocess

**Severity:** CRITICAL
**Category:** Injection (OWASP A03:2021)
**Location (planned):** brain.py

**Risk:** User question strings passed to shell commands allow OS command injection. Full system control on Raspberry Pi OMV.

**Prohibited:** os.system(user_input), os.popen(user_input), subprocess.run(user_input, shell=True), eval(user_input), exec(user_input) -- ALL FORBIDDEN if user data is involved.

**Required -- strict allowlist, user text never reaches subprocess:**
ALLOWED_COMMANDS dict maps safe keys to pre-approved command lists. AI classifier outputs a key string only. That key is validated against ALLOWED_COMMANDS. shell=False always.

---

### CRIT-4: SQL Injection in SQLite Queries

**Severity:** CRITICAL
**Category:** Injection (OWASP A03:2021)
**Location (planned):** brain.py

**Risk:** String-formatted SQL allows reading all DB contents and (if load_extension enabled) OS command execution.

**Prohibited:** cursor.execute(f"SELECT * FROM history WHERE q = '{user_input}'") and all string concatenation/formatting in SQL.

**Required -- parameterized queries only:**
cursor.execute("SELECT * FROM history WHERE q = ?", (user_input,)) -- always use ? placeholders.

**Required SQLite hardening on every connection open:**
conn.execute("PRAGMA trusted_schema = OFF")
conn.execute("PRAGMA secure_delete = ON")
conn.execute("PRAGMA journal_mode = WAL")
NEVER call conn.enable_load_extension(True)

## MEDIUM ISSUES - Must Fix Before Ship

---

### MED-1: CSRF on Flask POST Endpoints

**Severity:** MEDIUM
**Category:** CSRF (OWASP A01:2021)
**Location (planned):** app.py

**Risk:** Malicious page can use OMV admin session cookie to POST to /omv-agent/query.

**Required:** Enforce Content-Type: application/json on all POST endpoints. Validate Origin header against Host. No state-changing GET endpoints.

### MED-2: Flask Stack Traces Exposed to Client

**Severity:** MEDIUM
**Category:** Security Misconfiguration (OWASP A05:2021)
**Location (planned):** app.py

**Risk:** Default Flask error handling returns full Python stack traces including file paths and module names.

**Required:** app.config["DEBUG"] = False. Generic @app.errorhandler(Exception) returning only {"error": "An internal error occurred."} with status 500. Log full exception server-side only.

### MED-3: No Input Length Enforcement

**Severity:** MEDIUM
**Category:** Resource Exhaustion / DoS
**Location (planned):** app.py, nginx location block

**Required in app.py:** MAX_QUESTION_BYTES = 2048. Return 413 if exceeded.
**Required in nginx:** client_max_body_size 8k in /omv-agent/ location block.

### MED-4: No Rate Limiting on /query

**Severity:** MEDIUM
**Category:** DoS (OWASP A04:2021)
**Location (planned):** nginx location block

**Required (nginx):** limit_req_zone $binary_remote_addr zone=omv_agent:10m rate=10r/m; limit_req zone=omv_agent burst=5 nodelay; limit_req_status 429;

### MED-5: Unbounded Session History Table

**Severity:** MEDIUM
**Category:** Resource Exhaustion / Disk Exhaustion
**Location (planned):** brain.py

**Risk:** SD card on Raspberry Pi can fill up. OMV crashes.

**Required:** After every INSERT into history, DELETE rows exceeding MAX_HISTORY_ENTRIES = 500 (keep newest 500 only).

### MED-6: Systemd Service Privilege and Isolation

**Severity:** MEDIUM
**Category:** Privilege Escalation (OWASP A01:2021)
**Location (planned):** omv-agent.service

**Risk:** Service running as root means successful injection = full system compromise.

**Required systemd directives (all mandatory):**
User=www-data, Group=www-data, ProtectSystem=strict, ProtectHome=true, PrivateTmp=true, PrivateDevices=true, NoNewPrivileges=yes, ReadWritePaths=/var/lib/omv-agent /var/log/omv-agent, CapabilityBoundingSet= (empty), AmbientCapabilities= (empty), ProtectKernelTunables=yes, ProtectKernelModules=yes, ProtectControlGroups=yes, LimitNOFILE=1024, LimitNPROC=64

## LOW / INFORMATIONAL FINDINGS

---

### LOW-1: connect-src Not Explicit in Live CSP

**Severity:** LOW
**Source:** /etc/nginx/openmediavault-webgui.d/security.conf (confirmed live)

connect-src is absent and inherits default-src self. Behaviour is correct but implicit. If OMV changes default-src, connect-src silently changes. Document in deployment runbook. Do not edit security.conf -- it is auto-generated.

### LOW-2: unsafe-eval and unsafe-inline in Live CSP

**Severity:** LOW (existing OMV posture, not introduced by this project)
**Source:** /etc/nginx/openmediavault-webgui.d/security.conf (confirmed live)

CSP provides ZERO XSS protection due to unsafe-eval and unsafe-inline required by OMV Ext JS. Cannot be fixed -- auto-generated. CRIT-2 (textContent only) is the sole XSS defence.

### LOW-3: Knowledge Base Content Must Be Treated as Untrusted

**Severity:** LOW
**Location (planned):** brain.py, /usr/share/omv-agent/knowledge/

Knowledge base files loaded and rendered without sanitization become an XSS vector. If passed to subprocess, they become a command injection vector. All KB content must be treated as untrusted.

### LOW-4: No Audit Trail / Request Correlation

**Severity:** INFO
**Location (planned):** app.py

Without X-Request-ID headers, correlating malicious queries across nginx and Flask logs is difficult. Assign uuid.uuid4() per request and emit as X-Request-ID response header. Log request_id with every log entry.
